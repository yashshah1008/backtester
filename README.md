# Backtester

A full-stack rule-based strategy backtesting engine. Define a moving-average
crossover strategy on a stock ticker, run it against real historical price
data, and compare it to a buy-and-hold baseline with risk-adjusted metrics
(Sharpe ratio, max drawdown, win rate).

See [`DESIGN.md`](./DESIGN.md) for the full design doc (written before
implementation) covering scope, data model, and known limitations.

## Architecture

```
┌─────────────┐      REST/JSON      ┌──────────────────┐      ┌────────────┐
│   React     │ ───────────────────▶│  FastAPI backend  │─────▶│ PostgreSQL │
│  frontend   │◀─────────────────── │  + backtest engine│      │ (or SQLite)│
└─────────────┘                     └──────────────────┘      └────────────┘
                                              │
                                              ▼
                                       ┌─────────────┐
                                       │  yfinance   │
                                       │ (price data)│
                                       └─────────────┘
```

- **`backend/app/backtest.py`** — the core engine, written as pure functions
  with no DB/HTTP dependency, so the trading logic is testable in isolation.
- **`backend/app/routers/strategies.py`** — REST API (create strategy, run
  backtest, fetch results).
- **`backend/app/models.py`** / **`schemas.py`** — DB models and API
  contracts, kept deliberately separate.
- **`frontend/`** — React app (Vite + Tailwind + Recharts).

## Running locally

### Backend
```bash
cd backend
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```
API docs available at `http://localhost:8000/docs` (auto-generated by FastAPI).

### Frontend
```bash
cd frontend
npm install
npm run dev
```
Open `http://localhost:5173`. It talks to the backend at `http://localhost:8000/api`
by default (override with a `VITE_API_BASE` env var).

### Tests
```bash
cd backend
pytest -v
```

## CI/CD
GitHub Actions (`.github/workflows/ci.yml`) runs on every push/PR to `main`:
lints and tests the backend, builds the frontend. See the Actions tab for
run history.

## Deployment
- **Backend**: deploy `backend/` to Render or Railway as a web service
  (`uvicorn app.main:app --host 0.0.0.0 --port $PORT`). Set `DATABASE_URL`
  to a managed Postgres instance — no code changes needed, `database.py`
  reads it from the environment.
- **Frontend**: deploy `frontend/` to Render/Railway/Vercel as a static
  site (`npm run build` → serve `dist/`). Set `VITE_API_BASE` to the
  deployed backend's `/api` URL.

## Assumptions & known limitations
See the "Known limitations" section of [`DESIGN.md`](./DESIGN.md) — no
transaction costs, no shorting, single-ticker only in v1. Documented
deliberately rather than hidden, since being able to name a project's
limitations is as important as building it.
